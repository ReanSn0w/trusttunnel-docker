# Жизненный цикл TLS-сертификата

Контроллер хранит один выбранный источник сертификата и публикует проверенную
PEM-пару в постоянном volume. VPN endpoint на TCP 443 и встроенный HTTPS
AdminUI на TCP 8444 используют одну подтверждённую ревизию. Панель открывается
по DNS-домену сертификата. До первого успешного выпуска HTTPS недоступен;
healthcheck и журналы контейнера продолжают работать.

## Первый запуск и настройки

Выберите `TT_TLS_SOURCE`: `letsencrypt`, `self-signed` или `provided` и укажите
`TT_TLS_HOSTNAME`. Для Let's Encrypt также нужен `TT_ACME_EMAIL`. Старый способ
первичной настройки с одними `TT_TLS_HOSTNAME` и `TT_ACME_EMAIL` по-прежнему
выбирает Let's Encrypt. Поля PEM-пары допустимы только для `provided`, а email
ACME — только для `letsencrypt`. Режимы `production` и `staging` относятся к
Let's Encrypt и не являются отдельными источниками.

Переменные окружения задают только начальные значения. После первого сохранения
приоритет имеют данные SQLite. Несовпадение домена или источника при повторном
запуске записывается в лог; сертификат из-за него не заменяется. Источник можно
явно изменить на странице **TLS**. При смене действующая пара остаётся на месте,
пока новая не пройдёт проверку и публикацию.

Фоновый worker начинает проверку сразу после восстановления endpoint. Он
переиспользует подходящую сохранённую пару, проверяет настройки панели каждые
30 секунд и повторяет ошибки с ограниченной экспоненциальной задержкой и
случайным отклонением. Источник при ошибке автоматически не меняется.

## Let's Encrypt

Контроллер выпускает сертификат через ACME HTTP-01 на TCP 80 и продлевает его
перед истечением срока. Для выпуска требуется публичный DNS-домен и доступность
TCP 80. Staging используется только для проверки и не доверяется обычными
клиентами. Повторный старт с подходящей парой не создаёт новый ACME order.
Длина окна продления ограничивается сроком самого сертификата, чтобы
короткоживущая пара не вызывала непрерывные заказы. DNS-01 здесь нет.

## Self-signed

Контроллер создаёт сертификат ECDSA P-256 с SAN выбранного DNS-домена сроком на
365 дней. Ключ сохраняется во внутренней ревизии с правами `0600`; рестарт
переиспользует ту же пару и fingerprint. Перед истечением срока сертификат
ротируется. Установка нового сертификата на клиентах и повторный импорт
профиля могут понадобиться после ротации: проверьте, как именно клиент хранит
доверие. Публичную часть можно скачать на странице **TLS** после выпуска.
Приватный ключ через панель не отдаётся. Экспорт профиля не включает
`skip_verification` автоматически.

## Provided PEM

Подготовьте `cert.pem` с полной PEM-цепочкой и соответствующий `key.pem` в
отдельном каталоге на хосте. Пример read-only монтирования:

```sh
TT_PROVIDED_TLS_DIR=/srv/trusttunnel-certs \
  docker compose -f docker-compose.yml -f docker-compose.provided.yml up -d
```

В базовой конфигурации можно использовать собственное read-only монтирование и
задать `TT_TLS_CERTIFICATE_FILE` и `TT_TLS_KEY_FILE` как абсолютные пути внутри
контейнера. Оба файла проверяются вместе: SAN, срок, PEM-цепочка и соответствие
ключа. Лишь после успешной проверки пара копируется во внутреннюю ревизию; исходные
файлы контроллер не изменяет. При частичной или ошибочной замене прежняя рабочая
ревизия остаётся активной. Контроллер показывает приближение срока истечения,
но не пытается продлить предоставленный сертификат через ACME.

Старые вручную импортированные сертификаты мигрируют в источник `provided` без
удаления ключей. Если исходные пути тогда не сохранялись, контроллер продолжает
использовать внутреннюю копию; для фонового отслеживания замен нужно явно
указать смонтированные пути.

## Публикация и отказ

Пара ключа и сертификата хранится в одной версионированной директории.
Публикация обновляет TLS и конфигурацию endpoint под общей блокировкой с
изменениями пользователей. Без VPN-пользователей сертификат сохраняется, а
процесс endpoint запускается позже. Если проверка endpoint или запись метаданных
не проходит, контроллер возвращает предыдущую ревизию и фиксирует отказ в
истории. В истории и логах допустимы hostname, fingerprint, сроки и очищенное
сообщение об ошибке; приватный ключ и ACME challenge token туда не записываются.
При смене сертификата действующий VPN endpoint кратко перезапускается с новой
неизменяемой ревизией конфигурации, затем AdminUI активирует ту же пару. Это
нужно, потому что `SIGHUP` перечитывает файл `hosts.toml` по пути, указанному
при старте процесса, а старый путь остаётся привязан к предыдущей ревизии.
