## Что мы делаем?

После `automatic-tls-lifecycle.md` добавляем HTTPS непосредственно в Go AdminUI. VPN на 443 и панель на 8444 используют одну подтверждённую TLS-ревизию для общего домена при любом из трёх источников: Let's Encrypt, self-signed или provided. Поддерживаемого режима внешней TLS-терминации и HTTP-входа AdminUI больше нет. Переход существующих установок описываем как явное изменение развёртывания, без автоматического удаления контейнеров или данных.

## Для чего мы делаем?

Сейчас Nginx использует отдельные `admin.crt` и `admin.key`, тогда как контроллер управляет сертификатом VPN. Объединение устраняет ручную синхронизацию и позволяет заходить с телефона по обычному HTTPS без SSH-туннеля или привязки к IP клиента.

## План

- [ ] Сделать встроенный HTTPS единственным способом обслуживания AdminUI
  - [ ] Удалить ветку внешней TLS-терминации из запуска приложения.
  - [ ] Удалить HTTP listener AdminUI, включая варианты для внешнего reverse proxy.
  - [ ] Удалить настройки `TT_EXTERNAL_TLS` и `TT_TRUSTED_PROXY` с диагностикой устаревших параметров при миграции.
  - [ ] Исключить Nginx из поддерживаемых Compose-примеров.
  - [ ] Разделить внешние порты панели 8444 и VPN 443 в Compose.
  - [ ] Открывать ACME HTTP-01 listener на 80 только в режиме letsencrypt без маршрутов панели.
  - [ ] Сохранить отдельный непубличный HTTP healthcheck без доступа к AdminUI.
  - [ ] Документировать обращение к панели по домену сертификата, а не по IP.

- [ ] Подключить Go HTTPS к общему хранилищу сертификата
  - [ ] Добавить потокобезопасную загрузку подтверждённой TLS-пары для новых соединений AdminUI.
  - [ ] Исключить чтение сертификата и ключа из разных ревизий.
  - [ ] Подхватывать продление без рестарта контейнера.
  - [ ] Согласовать момент переключения AdminUI с успешной публикацией сертификата endpoint.
  - [ ] Откатывать HTTPS AdminUI на предыдущую пару при rollback общей ревизии.
  - [ ] Не публиковать непроверенный сертификат при ошибке записи метаданных.

- [ ] Реализовать безопасное поведение до первого выпуска
  - [ ] Оставить healthcheck и логи доступными при ожидании ACME.
  - [ ] Не открывать публичный HTTP-вход при отсутствии сертификата.
  - [ ] В режиме letsencrypt ожидать первый успешный выпуск без автоматического self-signed fallback.
  - [ ] В режиме self-signed запускать панель с общей сгенерированной парой.
  - [ ] В режиме provided запрещать HTTPS-запуск с отсутствующей или невалидной парой, сохраняя диагностику в логах.
  - [ ] При повторной ошибке источника продолжать использовать прежнюю действующую пару без смены режима.
  - [ ] Показывать в панели состояние и последнюю ошибку фонового выпуска.

- [ ] Сохранить защиту панели
  - [ ] Проверить Secure, HttpOnly и SameSite cookies во встроенном HTTPS-режиме.
  - [ ] Проверить CSRF для bootstrap, login и изменяющих запросов.
  - [ ] Игнорировать forwarded-заголовки при определении защищённости соединения и адреса клиента.
  - [ ] Проверить rate limit входа для прямого клиента со сменой мобильной сети.
  - [ ] Установить ограничения TLS и HTTP timeouts для публичного HTTPS listener.

- [ ] Проверить переход со старого развёртывания
  - [ ] Добавить TLS-handshake тест совпадения сертификата VPN и AdminUI.
  - [ ] Добавить тест обновления сертификата при продолжающей работать панели.
  - [ ] Добавить тест сохранения старой пары при ошибке renewal.
  - [ ] Проверить bootstrap и login в браузере на отдельном HTTPS-порту.
  - [ ] Проверить отказ от запуска со старыми настройками внешней TLS-терминации с понятной инструкцией миграции.
